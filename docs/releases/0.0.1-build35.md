# 0.0.1 build 35 preview

- Clear a stale connected state as soon as the active relay reports that the current recipient is unreachable. Reconnect with pending messages retained instead of waiting up to 65 seconds while retry attempts expire.
- Let an authenticated message retry reach durable receive handling even when the crypto layer has already seen its ID. This recovers an interrupted receive or missing receipt without adding duplicate chat bubbles.
- Recognize authenticated receipts that return over relay for messages originally sent through Direct.
- Wait for received text history to finish saving before acknowledging delivery. A failed write is retried when the message arrives again.

Verification includes reproducible regression tests, a real native Rust Noise session over a disposable public TryCloudflare relay, messages in both directions, an intentionally omitted receipt and recipient socket reconnection. Test accounts are isolated from user data. Direct WebRTC still depends on network reachability; the discovery seed does not carry messages or files.
